## 사양 축소 (1코어 6GB × 2대) — 2026-09-26 적용

용량이 통째로 열리지 않고 조각으로 열리면 2코어 요청은 그 조각에 들어가지 못한다.
1코어 6GB로 낮추면 들어갈 구멍이 넓어진다. 두 대를 합치면 2 OCPU / 12GB로 무료 한도를 정확히 채운다.

한 대만 잡혀도 쓸 수 있는 서버가 생기므로 손해는 없다. 1~2주 지켜보고 그래도 안 되면 유료 전환을 다시 검토한다.

구현에서 신경 쓴 부분:

- 매 실행 시작에 보유 대수를 세서 목표를 넘겨 만들지 않는다. 이름은 `<DISPLAY_NAME>-<번호>`이고 빈 번호를 재사용한다.
- 목록 조회가 인증 오류로 실패하면 0대로 오인하지 않고 그대로 실패시킨다.
- 한 대를 잡으면 즉시 이슈를 만들고, 대기 없이 곧바로 다음 대를 노린다. 용량이 열린 창이 짧기 때문이다.
- 확보 알림을 워크플로 스텝이 아니라 `catch.sh`에서 만든다. 러너가 죽으면 `always()` 스텝도 안 돌기 때문이다 (2026-09-26에 실제로 겪었다).
- 한 대라도 잡은 뒤 한도 초과가 나오면 실패가 아니라 정상 종료로 처리하고 워크플로를 끈다. 5시간마다 실패 메일이 쌓이는 걸 막는다.
- 부팅 볼륨은 대당 90GB다. 무료 블록 스토리지 총 200GB를 꽉 채우면 한도 초과로 확보가 막힌다.

## 확률에 대한 평가

- 잡을 확률을 코드로 올리는 건 "시도하는 시간을 늘리는 것"과 "요청 사양을 줄이는 것" 둘뿐이다. 나머지 수정은 잡았을 때 놓치지 않기 위한 안전장치다.
- 용량이 열리는 건 오라클 사정이고, 같은 방식으로 돌리는 계정이 많다. 시도가 늘면 확률은 오르지만 언제 잡힐지는 보장할 수 없다.
- 코드 밖에서 가장 효과가 크다고 알려진 방법은 유료(Pay As You Go) 전환이다. 아래 참고.

## 유료(Pay As You Go) 전환 검토 — 2026-09-06 보류

**장점.** 유료 계정은 용량을 우선 배정받는다는 보고가 많다. 다만 오라클이 공식으로 보장하는 건 아니고, 대개 몇 시간에서 며칠 안에 잡혔다는 경험담 수준이다.
Always Free 한도 안에서는 유료 계정도 과금되지 않는다. 공식 문서도 "유료로 전환해도 Always Free 리소스는 계속 무료이며 한도 초과분만 과금된다"고 명시한다.

축소된 2 OCPU / 12GB는 무료 계정에만 적용되고 유료 계정은 이전 한도인 4 OCPU / 24GB를 계속 무료로 쓸 수 있다는 지원팀 답변 보고가 있다.
공식 문서에는 계정 유형 구분이 없어 확정은 아니다.

**주요 무료 한도 (2026-09-26 공식 문서 확인).**

| 항목 | 한도 |
|---|---|
| Ampere A1 | 월 1,500 OCPU시간 + 9,000 GB시간 (2코어 12GB 상시) |
| AMD 마이크로 | 2대 (E2.1.Micro, 1/8코어 1GB) |
| 블록 스토리지 | 부팅 포함 총 200GB, 백업 5개 |
| 오브젝트 스토리지 | 표준 10GB + 저빈도 10GB + 아카이브 10GB |
| 아웃바운드 트래픽 | 월 10TB |
| 로드밸런서 | 1대 (10Mbps) |
| Autonomous DB | 2개 (1 OCPU, 20GB) |
| MySQL HeatWave | 1대 (50GB) |
| 이메일 발송 | 월 3,000건 |

**일본 계획과 충돌하는 점.** Always Free는 홈 리전에서만 적용된다.
유료로 전환하면 다른 리전을 구독할 수 있지만 거기서 만든 인스턴스는 과금된다.
즉 "유료 전환 + 일본 리전"은 매달 비용이 든다. 두 방법은 택일이다.

무료 계정에서는 7일간 CPU·네트워크·메모리 사용률이 20% 아래인 유휴 인스턴스를 오라클이 회수할 수 있다.

**위험.** OCI에는 지출 상한이 없다. Budget은 24시간마다 평가되는 알림일 뿐이고 리소스를 멈추지 않는다.
하드 리밋을 원하면 Events와 Functions로 컴파트먼트 쿼터를 걸어 신규 생성을 막는 구성을 직접 만들어야 한다.

트래픽 과금 구조:

- 들어오는 트래픽은 무료다. DDoS가 쏟아져도 인바운드는 청구되지 않는다.
- 나가는 트래픽은 월 10 TB까지 무료다 (공식 문서 확인). 초과분 단가는 GB당 $0.0085(북미·유럽) 또는 $0.025(아시아)로 알려져 있으나
  오라클 가격 페이지가 자동 조회를 막아 2026-09-26에 재확인하지 못했다. 아래 금액표는 이 단가를 가정한 값이다.
- 작은 API가 10 TB를 내보내려면 응답 1 KB 기준 100억 건이 필요하다. 2 OCPU로는 불가능하다.
- 현실적인 위험은 서버가 해킹당해 봇으로 아웃바운드를 뿜는 경우, 그리고 실수로 유료 리소스를 만드는 경우다.

이론상 최악 (A1 2 OCPU의 대역폭 상한 2 Gbps로 계속 송출):

| 상황 | 초과 egress | 예상 비용 (북미 / 아시아 리전) |
|---|---|---|
| 하루 종일 풀 대역폭 송출 | 약 11 TB | 약 $100 / $290 |
| 한 달 방치 | 약 640 TB | 약 $5,400 / $16,000 |

비용 집계는 최대 하루 늦으므로, 알림을 걸어 두면 실질 노출은 하루치 정도다.

**완화책.**

- Budget 알림을 $5 정도로 걸어 메일을 받는다.
- 자동 차단은 직접 만든다. 이 리포의 Actions와 OCI CLI로 하루 몇 번 사용량 API를 조회해 임계치를 넘으면 인스턴스를 STOP하거나 인터넷 게이트웨이 라우트를 뺀다.
- Cloudflare 무료 플랜을 앞에 두고 OCI 보안 목록에서 Cloudflare IP만 허용한다. 원 서버를 직접 때릴 수 없고 캐시로 egress도 줄어든다.
- 컴파트먼트 쿼터로 A1 외 셰이프와 추가 볼륨 생성을 0으로 막아 실수로 유료 리소스를 만들 수 없게 한다.
- SSH 키 인증만 허용하고 필요한 포트만 연다.

**결정 (2026-09-06).** 청구 위험이 완전히 0인 건 무료 계정뿐이라 보류했다.

**결정 (2026-09-26).** 먼저 무료 계정에서 1코어 6GB × 2대로 1~2주 지켜본다.
그래도 안 되면 유료 전환과 아래 리전 변경을 놓고 다시 판단한다.

## 리전 변경 (재가입) 절차

무료 계정은 홈 리전을 바꿀 수 없고 다른 리전을 구독할 수도 없다. 리전을 바꾸려면 새 테넌시가 필요하다.

**주의.**

- 오라클은 같은 카드, 전화번호, 이름으로 다시 가입하면 중복 계정으로 보고 거절하는 경우가 많다고 알려져 있다. 탈퇴 전에 재가입에 쓸 이메일과 결제 수단을 따로 준비한다.
- 테넌시 삭제는 처리에 며칠 걸린다.
- 일본 리전(`ap-tokyo-1`, `ap-osaka-1`)은 AD가 하나다. `OCI_ADS`에 하나만 적는다.
- 일본 리전도 붐빈다는 보고가 있다. 오사카가 도쿄보다 낫다는 경험담이 있지만 확인된 사실은 아니다.

**순서.**

1. 재가입용 이메일, 결제 수단 준비
2. 기존 테넌시 삭제 (콘솔 → 테넌시 세부정보 → 종료)
3. 재가입. 홈 리전은 가입 시 고른다 (`ap-osaka-1` 또는 `ap-tokyo-1`)
4. 새 테넌시에서 준비
   - 프로필 → API 키 추가 → 개인키 PEM 내려받기, 핑거프린트 확인
   - VCN 마법사("인터넷 연결이 있는 VCN 생성")로 VCN과 공인 서브넷 생성
   - 보안 목록에 앱 포트 인바운드 추가 (22는 기본으로 열려 있음)
5. README의 "나머지 값 찾는 법"으로 AD, 이미지, 서브넷 OCID 확인
6. 이 리포의 Secrets 갱신 (아래 표)
7. Actions 탭에서 워크플로가 켜져 있는지 확인. 꺼져 있으면 Enable

**바꿀 Secrets.**

| 이름 | 새 테넌시에서 |
|---|---|
| `OCI_CLI_USER` | 바뀜 |
| `OCI_CLI_TENANCY` | 바뀜 |
| `OCI_CLI_FINGERPRINT` | 바뀜 (새 API 키) |
| `OCI_CLI_KEY_CONTENT` | 바뀜 (새 API 키) |
| `OCI_CLI_REGION` | `ap-osaka-1` 또는 `ap-tokyo-1` |
| `OCI_SUBNET` | 바뀜 |
| `OCI_IMAGE` | 바뀜 (리전마다 이미지 OCID가 다름) |
| `OCI_SSH_PUBKEY` | 그대로 |
| `OCI_ADS` | 하나만 (예: `xxxx:AP-OSAKA-1-AD-1`) |

코드는 그대로 쓴다.
